# verify-gpf

Runs the real `gpf` CLI against a GPF instance that the run builds in its
own scratch directory, and keeps proof of the result. Every path below is
relative to the checkout root (the git worktree that holds this skill);
every helper finds the checkout on its own, so they can be called from any
directory.

A run is one directory, `.verify/<run id>/`:

- `.verify/<run id>/scratch/` — the copy of the fixture GRR, its
  definition, the GPF instance with its genotype storage, the drive inputs,
  the import work directory and a private `HOME` and `TMPDIR`. Removed by
  Cleanup.
- `.verify/<run id>/evidence/` — one subdirectory per drive. Kept.

`.verify/` is git-ignored, so no run output is ever committed, and every
write stays inside the worktree.

Feature files live in `features/`; `features/README.md` holds the baseline
preconditions (including how to set up this checkout's `.venv`), the
driving conventions, the proof rules and the feature index.

This skill was generated by `/create-verify-skill` (lchorbadjiev/skills
`engineering/create-verify-skill`). Its contract code is the copy
`scripts/verify-lib.sh`; the gpf code is `scripts/app.sh`.

## 1. Launch

Create the run, its GRR definition and its GPF instance:

```bash
RUN_ID=$(.claude/skills/verify-gpf/scripts/launch.sh)     # or: launch.sh my-run-id
RUN=.verify/$RUN_ID
cat "$RUN/scratch/grr.yaml" "$RUN/scratch/instance/gpf_instance.yaml"
```

A run id holds only lowercase letters, digits, `_` and `-`, and starts with
a letter or a digit (`^[a-z0-9][a-z0-9_-]*$`), because the contract makes it
a valid compose project suffix (`verify-gpf-<run id>`). verify-gpf starts no
containers, but the grammar is the same for every `verify-<app>` skill.
`launch.sh` rejects `.`, `..` and `Run1` and creates nothing. The default id
is `<date>-<time>-<pid>`.

`launch.sh` copies `core/tests/small/tools/fixtures/repo` to
`$RUN/scratch/grr` and writes `$RUN/scratch/grr.yaml`:

```yaml
id: fixture
type: directory
directory: '<absolute run path>/scratch/grr'
```

and `$RUN/scratch/instance/gpf_instance.yaml`:

```yaml
instance_id: verify_gpf
reference_genome:
  resource_id: genomes/mock
gene_models:
  resource_id: gene_models/mock
genotype_storage:
  default: verify_duckdb
  storages:
    - id: verify_duckdb
      storage_type: duckdb_parquet
      base_dir: "%(wd)s/genotype_storage"
```

`%(wd)s` is the instance directory, so the genotype storage is inside
scratch. The instance has no annotation (see the gotchas of
`features/import-genotypes.md`). The drives set `GRR_DEFINITION_FILE` to
the run's definition, `DAE_DB_DIR` to the run's instance and `HOME` to
`$RUN/scratch/home`, so `~/.grr_definition.yaml` and a `DAE_DB_DIR` of the
caller are never read. The definition names a local directory GRR, so no
repository request leaves the host.

## 2. Doctor

Doctor writes nothing outside the run's scratch directory. Run it before the first drive and again after any failed drive:

```bash
PATH="$PWD/.venv/bin:$PATH" .claude/skills/verify-gpf/scripts/doctor.sh "$RUN_ID"
```

It fails (exit 1) with a message naming the fix when:

- `import_genotypes` on `PATH` is not this checkout's `.venv/bin/` one (a
  conda env or another worktree's venv can shadow it). Fix:
  `export PATH="$PWD/.venv/bin:$PATH"`. If `.venv/bin/import_genotypes` is
  missing, set up the `.venv` first (`features/README.md`).
- `.venv/bin/python` does not import `gpf` from this checkout's `core/gpf`,
  or `gain` from this `.venv`. Fix: build the gain wheel and run `uv sync`
  (`features/README.md`).
- the fixture GRR lacks `genomes/mock` or `gene_models/mock`. Fix: restore
  `core/tests/small/tools/fixtures/repo`.
- the run's instance does not load: `GPFInstance.build` on
  `$RUN/scratch/instance/gpf_instance.yaml`, in the run's isolated
  environment, must give the reference genome `chrA` of length 100. The
  error output is in `$RUN/scratch/doctor-instance.err`.

To prove the `PATH` message, put a fake `import_genotypes` first on `PATH`:

```bash
mkdir -p "$RUN/scratch/fakebin"
printf '#!/bin/sh\nexit 0\n' > "$RUN/scratch/fakebin/import_genotypes"
chmod +x "$RUN/scratch/fakebin/import_genotypes"
PATH="$PWD/$RUN/scratch/fakebin:$PWD/.venv/bin:$PATH" \
    .claude/skills/verify-gpf/scripts/doctor.sh "$RUN_ID"    # exits 1, names the PATH fix
```

`VERIFY_GPF_FIXTURE_GRR=<dir>` makes Doctor (and Launch) read `<dir>`
instead of `core/tests/small/tools/fixtures/repo`, to prove the
missing-fixture message without touching the checkout:

```bash
mkdir -p "$RUN/scratch/empty-grr"
VERIFY_GPF_FIXTURE_GRR="$PWD/$RUN/scratch/empty-grr" PATH="$PWD/.venv/bin:$PATH" \
    .claude/skills/verify-gpf/scripts/doctor.sh "$RUN_ID"    # exits 1
```

## 3. Drive

One recipe per feature file. Drives always call the checkout CLI as
`.venv/bin/<tool>`, never the bare name from `PATH`.

**`features/import-genotypes.md`** — `import_genotypes` of a de novo study
into the run's instance:

```bash
.claude/skills/verify-gpf/scripts/drive-import-genotypes.sh "$RUN_ID"
```

which writes, under `$RUN/scratch/input/`, a pedigree of two trio families
(`f1`, `f2`), the de novo file

```
familyId	location	variant	bestState
f1	chrA:11	sub(A->C)	2 2 1/0 0 1
f1	chrA:23	sub(A->G)	2 2 1/0 0 1
f2	chrA:37	sub(A->T)	2 2 1/0 0 1
```

and the import project `import_project.yaml` (study id `verify_study`,
destination `verify_duckdb`, work directory `$RUN/scratch/work`), and runs,
from `$RUN/scratch/` in the isolated environment:

```bash
.venv/bin/import_genotypes -i $RUN/scratch/instance/gpf_instance.yaml -j 1 \
    $RUN/scratch/input/import_project.yaml
```

Then it runs `scripts/dump_study.py` in a separate `.venv/bin/python`
process: it builds the instance, loads `verify_study` and writes every
variant to `variants.tsv`. The drive exits 0 only when `import_genotypes`
exits 0, the dump exits 0 and the read-back check passes. On a non-zero
exit, run Doctor before anything else.

## 4. Evidence

Each drive keeps, in `$RUN/evidence/<feature>/`:

| File | Content |
| --- | --- |
| `command.txt` | the exact command, with its working directory and environment |
| `stdout.txt` / `stderr.txt` | the CLI's output streams |
| `exit_code.txt` | the CLI's exit code |
| `input.ped` / `input.tsv` / `import_project.yaml` | `import-genotypes`: the pedigree, the de novo file and the import project the drive fed in |
| `study.yaml` | `import-genotypes`: the study configuration that the import wrote into the instance |
| `storage_files.txt` | `import-genotypes`: the files that the import wrote under the genotype storage |
| `variants.tsv` | `import-genotypes`: the dump of the study by `dump_study.py`, the output that the read-back checks |
| `dump_stderr.txt` / `dump_exit_code.txt` | `import-genotypes`: the error stream and exit code of the dump |
| `readback.txt` / `readback_exit_code.txt` | the read-back of the output |

The dump is the second, independent read of the import: a separate process
builds the instance from its configuration and queries the study. The
read-back compares the dump with the exact values the input gives: the
families `f1`, `f2` and exactly the variants `f1 chrA:11 A>C`,
`f1 chrA:23 A>G` and `f2 chrA:37 A>T`, each with the best state
`2 2 1/0 0 1`. A dump with a lost, extra or changed variant fails it.
Re-run the read-back at any time, also after Cleanup:

```bash
.claude/skills/verify-gpf/scripts/readback-import-genotypes.sh "$RUN/evidence/import-genotypes/variants.tsv"
cat "$RUN/evidence/import-genotypes/exit_code.txt"
```

To prove that the read-back fails on a changed output, change one
alternative allele in a copy of the dump:

```bash
sed 's/\tA\tC\t/\tA\tG\t/' "$RUN/evidence/import-genotypes/variants.tsv" > "$RUN/scratch/variants-changed.tsv"
.claude/skills/verify-gpf/scripts/readback-import-genotypes.sh "$RUN/scratch/variants-changed.tsv"    # exits 1
```

Cite the evidence directory, not a pasted summary, as the proof.

## 5. Cleanup

`cleanup.sh` removes the scratch directory: the GRR copy, the instance with
its genotype storage, the inputs and the work directory. It keeps the
evidence directory. verify-gpf starts no containers, so there is no compose
project to bring down:

```bash
.claude/skills/verify-gpf/scripts/cleanup.sh "$RUN_ID"
ls "$RUN"                     # evidence only
git status --porcelain        # shows no run output
```

## 6. Helpers

All in `.claude/skills/verify-gpf/scripts/`; the `.sh` files are
executable:

| Script | Invocation | Does |
| --- | --- | --- |
| `launch.sh` | `launch.sh [run id]` | creates `.verify/<run id>/{scratch,evidence}`, copies the fixture GRR to scratch, writes `scratch/grr.yaml` and `scratch/instance/gpf_instance.yaml`; prints the run id |
| `doctor.sh` | `doctor.sh <run id>` | preflight that writes nothing outside the run's scratch directory (`import_genotypes` on `PATH`, the `gpf` and `gain` import paths, the fixture GRR, the run's instance loads) |
| `drive-import-genotypes.sh` | `drive-import-genotypes.sh <run id>` | imports the de novo study with `import_genotypes`, dumps it with `dump_study.py`, keeps the evidence, runs the read-back |
| `dump_study.py` | `.venv/bin/python -I dump_study.py <gpf_instance.yaml> <study id>` | builds the instance, loads the study and prints its families and variants as a sorted TSV |
| `readback-import-genotypes.sh` | `readback-import-genotypes.sh <variants.tsv>` | checks the families `f1`, `f2` and the three variants with their best states |
| `cleanup.sh` | `cleanup.sh <run id>` | removes `.verify/<run id>/scratch/`, keeps the evidence |
| `app.sh` | sourced by the launch, doctor, drive and cleanup scripts | the gpf code: `VERIFY_APP=gpf`, the `.venv` path, the fixture GRR, the study id, `app_env` (`GRR_DEFINITION_FILE`, `DAE_DB_DIR`), the CLI and import-path checks; sources `verify-lib.sh` |
| `verify-lib.sh` | sourced by `app.sh` only | the copy of the canonical contract code from lchorbadjiev/skills (run-id check, run layout, isolated `HOME`/`TMPDIR`/XDG environment, `verify_drive`, `verify_readback`, the compose helper); do not edit below its first line |

A full run, from the checkout root:

```bash
S=.claude/skills/verify-gpf/scripts
RUN_ID=$($S/launch.sh)
PATH="$PWD/.venv/bin:$PATH" $S/doctor.sh "$RUN_ID"
$S/drive-import-genotypes.sh "$RUN_ID"
$S/cleanup.sh "$RUN_ID"
ls .verify/$RUN_ID/evidence/import-genotypes
```
